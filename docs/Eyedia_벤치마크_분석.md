# Eyedia (2025 한이음 금상) 벤치마크 분석 — KYUL이 가져갈 것

> **왜 이 작품인가**: 2025 수상작 중 **KYUL과 기술 스택이 가장 가까운 사례**입니다. 시선 추적 + RAG + LLM. 같은 재료로 한쪽은 금상, 한쪽은 중간평가 탈락. 재료가 같으니 **차이가 설계에 있다는 게 분명해집니다.**
>
> ⚠ **정보 한계**: 한이음은 수상작 보고서 원문을 공개하지 않습니다. 아래 「확인된 사실」은 언론 보도 3건에서 확인한 것이고, 「구조 분석」부터는 **그 사실로부터의 제 추론**입니다. 구분해서 읽으십시오.

## 1. 확인된 사실

| 항목 | 내용 |
|---|---|
| 팀명 | **무물매니저** (덕성여자대학교 컴퓨터공학과) |
| 작품명 | **Eyedia** — 스마트 아이웨어 기반 AI 도슨트 플랫폼 |
| 수상 | **금상** (2025 한이음 드림업 엑스포) |
| 기술 구성 | **시선·작품 추적 카메라**, **RAG 기반 지식 검색**, **LLM 설명 생성** |
| 기능 | 관람객 **시선 추적으로 개별 작품 맞춤 해설** 제공, 미술관 정보 조회, 작품 스크랩 |
| 하드웨어 | 스마트 아이웨어 (착용형 디바이스) |

같은 해 시상 규모: 대상 3 / **금상 7** / 은상 14 / 동상 16 / 장려상 85 = 총 125팀.
→ **금상은 상위 10팀 이내**입니다.

## 2. 구조 분해 (추론)

### 2.1 Eyedia의 핵심 루프

```
관람객이 작품을 본다
   ↓
시선·작품 추적 카메라가 "어느 작품인지" 특정          ← ★ 이름을 가진 결과
   ↓
그 작품을 키(key)로 지식베이스 검색 (RAG)
   ↓
LLM이 그 작품에 대한 해설 생성
   ↓
관람객에게 전달
```

### 2.2 이 루프가 심사에서 강한 이유 6가지

**① 중간 산출물이 "이름"을 가진다**
시선 추적의 출력이 `41%` 같은 숫자가 아니라 **`<이 작품>`** 이라는 식별된 대상입니다. 이름이 있으면 맞았는지 틀렸는지가 판정됩니다.

**② 실패가 즉시 드러난다**
엉뚱한 작품의 해설이 나오면 그 자리에서 끝납니다. 숨을 곳이 없는 설계이고, **숨을 곳이 없는 설계는 그 자체로 신뢰의 근거**입니다. 심사위원은 "이건 진짜 동작하는구나"를 데모 30초로 확인합니다.

**③ RAG의 지식베이스가 외부에 실재한다**
미술관 도록, 작가 정보, 작품 해설. **세상에 이미 있고 출처가 명확한 문서**입니다. "RAG를 씁니다"가 아니라 "이것을 검색합니다"가 성립합니다.

**④ LLM 출력이 검증 가능하다**
해설이 그 작품에 관한 것인가 — 사람이 읽으면 압니다. 환각 여부가 눈에 보입니다.

**⑤ 하드웨어가 있다**
2025 대상 3팀이 전부 HW(요리 로봇 / 스마트 디바이스 / 센서 탑재 빗)였습니다. 착용형 디바이스는 난이도 항목에서 유리하게 작동합니다.

**⑥ 공익 소재**
도슨트 인력 부족, 관람 접근성. 수익보다 문제 해결 쪽 프레임입니다.

## 3. KYUL과 정면 비교

같은 재료가 어디서 갈렸는지가 한 표에 보입니다.

| 축 | **Eyedia (금상)** | **KYUL** |
|---|---|---|
| 시선 추적의 출력 | **작품 ID** — 이름 있는 대상 | **밝기 분산 → 시선이탈률 %** — 이름 없는 숫자 |
| 그 다음 단계 | 작품을 키로 RAG 검색 → 해설 | 6대 역량 점수 변환 → 갭 → 위험등급 (**3단계 추상화**) |
| 맞았는지 확인 | **즉시 가능** | 불가능 |
| RAG 지식베이스 | 미술관 도록 — **외부 실재, 출처 명확** | 사용자가 붙여넣은 JD·자소서 — 사용자마다 품질 편차 |
| LLM 출력 검증 | 사람이 읽으면 앎 | 검증축 없음 |
| 실패의 가시성 | 숨을 곳 없음 | 드러나지 않음 |
| 하드웨어 | 스마트 아이웨어 | 없음 (순수 웹) |
| 데모 | **쓰고 걸어다니면 끝** | 화면 캡처 나열 |
| 공익 프레임 | 도슨트 접근성 | "B2B SaaS 확장" 강조 |

### 3.1 한 문장으로

> **기술의 출력이 "이름을 가진 대상"에 닿는가.**
>
> Eyedia의 시선 추적은 **작품**에 닿습니다. KYUL의 시선 추적은 **점수**에서 끝납니다.
> 점수는 틀릴 수 없고, 틀릴 수 없는 것은 맞을 수도 없습니다. 심사위원이 검증할 수 없는 출력은 주장으로 분류됩니다.

**KYUL이 부족한 건 기술이 아니라 "검증 가능한 지점"입니다.** 그리고 이건 알고리즘을 갈아엎지 않고도 만들 수 있습니다.

## 4. KYUL이 가져갈 것 4가지

### ① 중간 산출물에 이름을 붙여라 【6일 내 가능 · 최우선】

**현재 구조**
```
시선 이탈률 41%  →  적극적 소통 62점  →  갭 −35.0pt  →  High Risk
                     (근거 없음)        (임계값 없음)     (해석 불가)
```

**바꿀 구조 — 점수 옆에 "사건"을 놓기**
```
Q3. "실패했던 경험을 말씀해 주세요"          (0:00 ~ 1:24)
──────────────────────────────────────────────
  0:08   시선 이탈 시작 — 12초간 화면 밖 응시
  0:31   발화 속도 급상승  3.2 → 5.1 음절/초
  0:47   무음 3.4초
  1:02   "어… 그러니까" 연속 4회
──────────────────────────────────────────────
  평소 대비: 시선 이탈 18% → 41%,  발화 속도 +59%
```

이건 점수가 아니라 **관찰 기록**입니다. 심사위원은 이 화면 캡처 하나로 "진짜 측정했구나"를 압니다. 알고리즘이 밝기 분산이든 랜드마크든, **관찰 기록으로 제시되는 순간 검증 가능한 산출물이 됩니다.**

그리고 사용자에게도 점수보다 훨씬 유용합니다. "적극적 소통 62점"보다 "3번 질문에서 12초간 시선을 피했습니다"가 행동으로 이어지니까요.

> 이게 Eyedia의 `작품 ID`에 해당하는 자리입니다.

---

### ② RAG의 지식베이스를 외부 실재 데이터로

**현재**: 사용자가 붙여넣은 JD·자소서만. → 사용자 입력 품질에 전적으로 종속. "RAG를 쓴다"는 말은 있으나 **무엇을 검색하는지가 없습니다.**

**추가할 것**
| 지식베이스 | 출처 | 용도 |
|---|---|---|
| 실제 채용공고 코퍼스 | 공개 채용 페이지, 채용 사이트 공개 공고 | 직무별 요구역량 추출, 질문 생성 근거 |
| 직무별 기술 개념 문서 | 공개 기술 문서 | 기술 꼬리질문 생성 |
| 면접 질문 뱅크 | 공개 자료 + 자체 구축 | 질문 시드 |
| **기업 인재상·핵심가치** | **채용공고에 실제로 명시됨** | **컬처핏 매칭** |

**부수 효과가 큽니다** — 네 번째 항목이 현재 "(데모 데이터)"로 표기된 컬처핏 문제를 그대로 해결합니다. 기업 인재상은 채용공고에 실제로 적혀 있으니 가상 기업("테크코어랩스 98% 일치")을 쓸 이유가 없습니다.

Eyedia가 미술관 도록을 가진 것처럼, KYUL은 **채용공고**를 가지면 됩니다.

---

### ③ 검증축을 하나 만들어라 【이게 진짜 승부처】

Eyedia에게 "작품을 맞췄나"가 검증축이었습니다. KYUL에도 하나 필요합니다. 후보 셋, 난이도 순:

**(a) 근거 인용 정확도 — 반나절, 자동 측정**
LLM 피드백이 인용한 답변 문장이 실제 원문에 존재하는가. 문자열 매칭으로 자동 산출되고, **100%가 나와야 정상**입니다. "우리는 환각을 제어했다"의 유일한 증거가 됩니다.

**(b) 질문 적합성 — 반나절**
생성된 면접 질문 30개를 3명이 교차 평가(적합/부적합). 일치도까지 내면 더 좋습니다. "RAG가 실제로 직무에 맞는 질문을 만드나"에 대한 답.

**(c) 기저선 재현성 (test-retest) — 이게 가장 강합니다**

> 같은 사람이 **다른 날 자가분석을 2회** 수행 → 6대 역량 점수의 상관계수

**이게 곧 이 서비스의 존재 증명입니다.** KYUL의 전제는 "기저선은 그 사람의 안정적 특성"인데, 재현되지 않으면 갭 분석 전체가 무의미해집니다. 반대로 상관이 나오면 **"우리 기저선은 재현됩니다"** 라는 한 문장을 쓸 수 있고, 이 문장은 서류의 다른 어떤 주장보다 무겁습니다.

비용: 파일럿 15명 중 **5명만 이틀에 걸쳐 2회**. 추가 1시간.

> ⚠ 참고로 현재 점수 산출식에 **랜덤 노이즈 ±3pt**가 들어 있습니다. 재현성 측정을 하려면 이걸 먼저 제거해야 합니다. 두 작업이 자연히 묶입니다.

---

### ④ 하드웨어가 없으면 "데이터"를 자산으로

대상권 3팀이 전부 HW였습니다. 순수 웹 서비스가 난이도를 증명하는 길은 **자체 데이터셋 또는 자체 모델**입니다.

KYUL은 이미 하나 가지고 있습니다 — **TTS 파인튜닝** (AI Hub 21,000쌍 → 4단계 전처리 → LoRA r=8/α=16). 서류에서 유일하게 "완료"된 딥러닝 자산인데 65페이지쯤에 묻혀 있습니다.

여기에 파일럿에서 나올 **"평상시–면접 멀티모달 대조 데이터셋"** 을 얹으십시오. 개발보고서에 이미 이런 문장이 있습니다:

> "본 솔루션의 '멀티모달 면접 데이터셋'은 향후 AI 기반 채용 시장의 평가 기준을 고도화하는 데 기여할 수 있는 높은 산업적, 학술적 가치를 지닙니다."

**지금은 데이터가 0건이라 공허한 문장입니다.** 15명분이 실재하는 순간 이 문장이 살아납니다. 같은 문장인데 무게가 완전히 달라집니다.

## 5. 온음(ON-UM, 금상)에서 가져갈 것 — 프레이밍

같은 해 금상인 **콜프로텍터**의 온음은 기술적으로 KYUL과 더 가깝습니다. **통화 음성 실시간 분석 → 폭언 감지.** KYUL의 SER·음향 분석과 사실상 같은 기술 영역입니다.

그런데 팔린 건 기술이 아닙니다.

> **"감정노동자를 지킨다"**

기술은 음성 분석인데, 서사는 **전화 상담원이 겪는 언어폭력**입니다. 심사위원이 기억하는 건 후자입니다.

**KYUL 번역:**

| 현재 (서류에 쓰인 것) | 번역 |
|---|---|
| "구직자의 성향을 객관적으로 진단" | "면접 컨설팅 비용을 감당할 수 없는 청년도 반복 훈련할 수 있게" |
| "컬처핏 기반 기업 매칭으로 조기 퇴사 방지" | "정보가 부족한 비수도권 구직자의 기회 격차를 줄인다" |
| "B2B SaaS·기업 HR 스크리닝으로 확장" | "대학 취업지원센터·학생상담센터 연계" |
| "높은 비즈니스 잠재력" | "웹캠·마이크 없이 텍스트로도 이용 가능 — 접근성" |

**같은 제품, 다른 문장입니다.** 2025 수상팀 후기에도 평가자들이 *"수익적인 목적보다 문제를 해결해줄 수 있는 주제"*, *"사회적 공헌도가 높은 주제"* 를 선호했다는 서술이 있습니다.

## 6. 현실적 목표 설정

```
대상 3팀   ← 전부 하드웨어. 순수 웹 서비스로는 구조적으로 어려움
금상 7팀   ← Eyedia 위치. 착용형 디바이스 + 검증 가능한 루프
─────────────────────────────────────────
은상 14 / 동상 16  ← ★ KYUL의 현실적 목표 구간
─────────────────────────────────────────
장려상 85팀        ← 참가 상위권이면 대체로 도달
```

**동상 이상(상위 32팀)에 들어가려면 4장의 4가지 중 최소 2개**가 필요합니다.
6일 안에 가능한 조합: **① 관찰 기록 타임라인 + ③(c) 기저선 재현성 검증.**

이 둘이면 "검증 가능한 산출물"과 "존재 증명"이 동시에 생깁니다. ②(채용공고 코퍼스)와 ④(데이터 자산)는 문서상 계획으로만 써도 됩니다.

## 7. 정리

| Eyedia가 한 것 | KYUL의 대응 수 |
|---|---|
| 시선 추적 → **작품 ID** (이름 있는 대상) | 점수 옆에 **관찰 기록 타임라인** |
| RAG 지식베이스 = **미술관 도록** (외부 실재) | RAG 지식베이스 = **실제 채용공고** |
| "작품을 맞췄나"라는 **검증축** | **기저선 재현성** (test-retest) |
| **스마트 아이웨어** (하드웨어 자산) | **자체 데이터셋 + TTS 파인튜닝** (데이터 자산) |
| 도슨트 접근성 (**공익**) | 취업 준비 기회 격차 (**공익**) |

**Eyedia와 KYUL의 차이는 기술력이 아니라 "자기 기술이 맞았는지 확인할 수 있게 설계했는가"입니다.**

KYUL의 기저선 갭 아이디어는 Eyedia의 시선-작품 매칭보다 오히려 독창적입니다. 다만 지금은 그 독창성이 **검증 불가능한 형태로 포장**되어 있어서, 심사위원이 좋다/나쁘다를 판단할 수조차 없는 상태입니다.

판단할 수 없으면 점수를 줄 수 없습니다. **검증 가능하게 만드는 것이 6일 작업의 전부입니다.**
