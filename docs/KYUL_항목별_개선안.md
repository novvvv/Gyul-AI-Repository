## 0. 이 문서를 관통하는 3가지 원칙

수상작에서 가져올 것은 기술이 아니라 **판정 가능성**입니다.

> Eyedia의 시선 추적은 **작품(이름 있는 대상)** 에 닿고, KYUL의 시선 추적은 **점수** 에서 끝납니다.
> 점수는 틀릴 수 없고, 틀릴 수 없는 것은 맞을 수도 없습니다. 검증할 수 없는 출력은 주장으로 분류됩니다.

아래 13개 항목 전부에 같은 3원칙을 적용합니다.

| 원칙 | 문장 | 적용 방식 |
|---|---|---|
| **P1. 이름 있는 산출물** | 모든 지표는 **관찰 기록(사건)** 에 닿는다 | 점수로 끝나는 슬라이드 금지. `0:31 발화속도 3.2→5.1` 같은 타임스탬프 이벤트를 산출물로 정의 |
| **P2. 상태 라벨 통일** | 모든 주장 옆에 `[측정됨] / [구현됨·미측정] / [설계]` | 요구사항·프로그램목록·알고리즘·성숙도매트릭스가 **같은 라벨**을 씀. 과장하지 않는 대신 어긋나지 않음 |
| **P3. 문서 간 추적성** | 요구사항ID ↔ 유즈케이스ID ↔ 화면ID ↔ 알고리즘번호 ↔ 테이블 | 각 장 하단에 상호참조 한 줄. 심사위원이 표본 검증할 때 뚫리지 않음 |

**서사 프레임(전 항목 문장 톤)**: "B2B SaaS 확장·기업 HR 스크리닝" → **"대학 취업지원센터 연계 / 면접 사교육비 부담 없는 반복 훈련 / 웹캠 없이 텍스트로도 이용 가능"**. 과기정통부 사업 프레임과 맞고, 생체정보 윤리 리스크도 같이 내려갑니다. 동시에 **"진단 도구"가 아니라 "자기주도 연습 도구"** 로 자칭을 바꿉니다.

## 2. 요구사항 정의서 — 5장 → 3장

**현재 (p8–12)**: 접속관리 / 마이페이지 / 자기분석 / 가상면접 / 리포트를 기능군당 1장씩. 표만 있고 우선순위·검증기준·상태가 없음.

**문제**
- 회원가입·로그인 CRUD와 "기저선 생성"이 **같은 무게**로 배치됨 → 무엇이 이 프로젝트의 요구사항인지 안 보임
- 비기능 요구사항이 유즈케이스 장(p14) 안에 숨어 있음
- p14 "음성·영상 스트림은 분석 후 즉시 폐기, 원본 미저장" ↔ 구성도의 S3 저장 · `Chat_Log.audio_url` **정면 충돌** ← 심사위원이 잡으면 신뢰 전체가 흔들림

**개선안**

| 슬라이드 | 내용 | 비고 |

| **REQ-2** | **핵심 요구사항 4건 심화** — ①기저선 생성 ②갭 산출 ③관찰 기록 생성 ④접근성(텍스트 대체 모드) | 각 건에 수용기준(AC)을 `~일 때 ~를 만족한다` 형태로 |
| **REQ-3** | 비기능 요구사항 — 성능 / **프라이버시** / 안정성 / 접근성 / **윤리(동의·보관기간·파기)** | p14에서 이동. 프라이버시 문구는 ERD·구성도와 **하나로 통일** |

**반드시 결정할 것**: 원본 저장 정책. 권장은 *"원본 스트림은 세션 종료 시 파기, 지표값과 전사 텍스트만 보존"* → 그러면 ERD의 `audio_url`을 삭제해야 함(§7 참조).

## 3. 유즈케이스 정의서 — 8장 → 3장

**현재 (p13–20)**: UC-01(자기분석) 상세 2장 + 다이어그램 6장(전체목록 1 + 기능군별 5).

**문제**: p16~p20 다섯 장이 "액터 —— 유즈케이스" 선 긋기의 반복입니다. 배점이 붙지 않는 지면입니다. 반대로 **상세 명세는 UC-01 하나뿐**이고, 정작 서비스의 심장인 **갭 산출**에는 유즈케이스가 없습니다.

**개선안**

| 슬라이드 | 내용 |
|---|---|
| **UC-1** | 유즈케이스 다이어그램 **1장 통합** — 5개 서브시스템을 패키지로 묶어 한 화면. (p15 확장) |
| **UC-2** | 유즈케이스 **목록표** — `UC-ID / 명 / 액터 / 중요도 / 난이도 / 연계 알고리즘 A번 / 관련 화면ID` ← **P3 추적성의 허브** |
| **UC-3** | **UC-핵심 상세 = "기저선–면접 갭 산출"** (현 UC-01은 이 장에 요약 병합) |

**UC-3 예외 시나리오에 넣을 것** (여기가 "난이도" 배점이 붙는 자리):
- A1. 기저선 세션과 면접 세션의 **조명·기기·마이크가 다를 때** → 세션 메타 기록 후 정규화, 편차 초과 시 재측정 안내
- A2. **4턴 미만 종료** → 기저선 미확정 처리, 갭 분석 차단
- A3. **기저선 재현성 미달**(test-retest 상관 낮음) → 갭 해석 보류 라벨
- A4. 웹캠·마이크 미보유 → **텍스트 전용 모드**로 6대 역량 중 텍스트 기반 지표만 산출(공익·접근성 프레임과 직결)

## 4. 서비스 흐름도 — 1장 → 2장

**현재 (p21)**: 로그인 → 대시보드 → 자가분석 → 화상면접 → 리포트의 **화면 전이도**. 사실상 내비게이션 순서도이고 "데이터"가 없습니다.

**문제**: 산출물 표(p2)에서 응용SW(인공지능) 트랙의 필수 항목은 **"서비스 흐름도(데이터 흐름도)"** ○ 입니다. 현재 장은 데이터 흐름도가 아닙니다.

**개선안**

| 슬라이드 | 내용 |
|---|---|
| **FLOW-1** | 현행 여정 흐름도 유지 + 각 단계 하단에 **그 단계가 생성하는 데이터 객체** 명시 — 자가분석 → `baseline_vector(6)`, 면접 → `session_metrics(≤40 samples)`, 리포트 → `gap_report + observation[]` |
| **FLOW-2** | **신규 · 데이터 흐름도(DFD)** — 원천(웹캠 프레임 / PCM / STT 텍스트 / JD·자소서) → 처리(VAD · 지표추출 · textSignals · RAG · 갭산출) → 저장(무엇을 얼마나) → 출력. 화살표마다 **형식 · 주기(400 ms) · 상한(40 샘플) · 보존기간** |

FLOW-2는 §10 데이터 윤리 표와 1:1로 맞물립니다. 같은 사실을 **아키텍처 언어**와 **거버넌스 언어**로 두 번 보여주는 것이라 두 항목에서 각각 점수가 붙습니다.

## 7. 엔티티 관계도 ERD — 2장 유지 (내용 전면 재설계)

**현재 (p52–53)**: MySQL ERD 한 장을 좌(L)/우(R)로 잘라 2장. 텍스트가 추출되지 않는 이미지이고, 잘린 관계선은 읽히지 않습니다.

**문제 (형식보다 내용)**
- 서비스의 정체성이 **"같은 사람의 두 상태 비교"** 인데, 스키마에서 **기저선 세션과 면접 세션의 관계가 보이지 않음**
- `Chat_Log.audio_url` ↔ 비기능요구 "원본 미저장" 충돌
- `Voice_Metric`에 **감정 컬럼 없음** ↔ 개발보고서의 "SER로 불안·자신감 정밀 분류" 주장 충돌

**개선안**

| 슬라이드 | 내용 |
|---|---|
| **ERD-1** | **핵심 서브 ERD** — `Member – Session(type: BASELINE \| INTERVIEW) – Metric – GapReport – Observation` 5~6 테이블만. **`Session.type` 하나로 두 상태를 같은 스키마에 담는다**는 점을 캡션으로 명시 → "개인 내 비교"라는 기획 주장의 **구조적 증거** |
| **ERD-2** | 전체 ERD 1장(가독 가능한 축소판) + **변경 이력 3줄**: `audio_url 제거(원본 미저장 정책 반영)` / `Voice_Metric emotion 컬럼 — SER 구현 여부에 맞춰 추가 또는 서술 삭제` / `MySQL 5.1.73 → 8.x` |

**신규 테이블 `Observation`** (P1의 실체): `observation_id, session_id, t_start, t_end, metric, value_baseline, value_session, evidence_text`
