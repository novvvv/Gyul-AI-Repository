## 0. 원칙

이 시스템은 규칙 세 개로 요약된다.

| # | 원칙 | 이유 |
|---|---|---|
| 1 | **UI에는 채도를 쓰지 않는다** | 화면에서 색이 보이면 그건 언제나 감정 데이터라는 뜻이 되도록. 버튼·탭·강조는 전부 BLACK과 WHITE SAND의 단계로 만든다. |
| 2 | **감정 색은 라벨에 고정한다** | 「기쁨」은 어느 화면 어느 차트에서도 같은 색이어야 한다. 정렬 순서나 인덱스로 색을 배정하지 않는다. |
| 3 | **테두리보다 여백** | 상자를 겹겹이 두르지 않는다. 구분은 간격과 1px 라인으로 한다. |

## 1. 색

### 1.1 브랜드 3색

| 이름 | HEX | RGB | Pantone | 역할 |
|---|---|---|---|---|
| WHITE | `#FFFFF7` | 255 255 247 | 663 C | 페이지 바탕 |
| WHITE SAND | `#E7E7DD` | 231 231 221 | 427 C | 라인 · 면 강조 |
| BLACK | `#1D1D1B` | 29 29 27 | Black C | 본문 · 상호작용 |

### 1.2 표면 — WHITE에서 WHITE SAND로 내려가는 4단계

```css
--bg:        #FFFFF7;  /* 페이지 바탕 (WHITE) */
--surface:   #FFFFFF;  /* 떠 있는 카드 — 바탕보다 한 단계 밝게 */
--sunken:    #FAFAF3;  /* 입력줄, 질문 블록처럼 살짝 내려앉은 면 */
--surface-2: #F2F2E9;  /* 칩, 강조행, 트랙 */
--surface-3: #E7E7DD;  /* 가장 진한 면 (WHITE SAND) */
```

> 페이지가 웜화이트(`#FFFFF7`)이므로 **카드는 순백(`#FFFFFF`)** 을 쓴다.
> 흰 위에 흰을 얹는 게 아니라, 미색 위에 흰을 얹어 카드가 떠 보이게 하는 구조다.

### 1.3 먹 — BLACK에서 올라오는 3단계

```css
--ink:   #1D1D1B;  /* 제목, 본문, 큰 수치 */
--ink-2: #5C5C56;  /* 보조 텍스트, 설명문 */
--ink-3: #96968C;  /* 캡션, 라벨, 비활성 */

--line:      #E7E7DD;  /* 구분선, 테두리 */
--line-soft: #F0F0E6;  /* 섹션 내부의 옅은 구분선 */
```

### 1.4 색이 나타나도 되는 곳 — 두 군데뿐

감정 색은 **감정 비중 스택 바**와 **발화별 타임라인**, 이 두 차트에만 면으로 쓴다.
그 밖의 모든 자리(면접 화면 신호, 인용 메타, 표 셀, 랜딩 미리보기)에서는
**9px 색 점 하나 + 감정 이름 텍스트**로만 표현한다.

```
❌ 슬픔 68%를 파란 프로그레스 바로            → 화면에서 가장 큰 색 덩어리가 됨
✅ ● 슬픔  68%  (점 9px + 텍스트, 수치는 먹색)  → 색은 식별용, 크기는 텍스트가 담당
```

레이더 차트도 감정 색을 쓰지 않는다. 두 계열(내 성향 / 문화)은
**BLACK 실선 + `--ink-3` 점선**으로 구분한다 — 감정이 아니라 비교이기 때문이다.

이 규칙이 없으면 브랜드가 3색인데 화면은 7색으로 보인다.

### 1.5 상호작용 — 별도 강조색을 두지 않는다

```css
--accent:      #1D1D1B;  /* = BLACK */
--accent-ink:  #FFFFF7;  /* 검정 면 위의 글자 */
--accent-wash: #F2F2E9;  /* 강조 배경 */
```

브랜드 팔레트에 액센트 컬러가 없다. 파랑 같은 색을 새로 만들어 넣으면 감정 데이터 색과 싸우므로,
**검정을 상호작용 색으로 쓴다.** 기본 버튼·선택된 탭·현재 진행 표시는 전부 검정 면이다.

**강조가 필요한데 검정을 못 쓰는 자리**(이미 검정 텍스트가 있는 곳)는 색 대신 **면**으로 처리한다:

| 상황 | 처리 |
|---|---|
| 불일치 지표 카드 | `--surface-2` 배경 + 라벨 굵게 |
| 불일치 표 행 | `--surface-2` 배경 + 왼쪽 2px 검정 바 |
| 불일치 안내 블록 | `--surface-2` 배경 + 왼쪽 2px 검정 보더 |
| 타임라인 불일치 칸 | 아래 2px 검정 밑줄 + 번호 굵게 |

### 1.6 감정 색 — 유일한 채도

7개 감정 라벨에 색을 **고정**한다. `EMOTION_LABELS`(`frontend/src/config.ts`)의 7종과 1:1 대응.

```css
--e-happiness: #D99411;  /* 기쁨 */
--e-fear:      #CE81A8;  /* 두려움 */
--e-sadness:   #2E7FBE;  /* 슬픔 */
--e-disgust:   #12A07C;  /* 혐오 */
--e-angry:     #DC6B1C;  /* 분노 */
--e-surprise:  #63AEDC;  /* 놀람 */
--e-neutral:   #A8A89C;  /* 중립 — 의도적 무채색 */
```

**「중립」만 무채색인 이유**: 중립은 기준선이지 하나의 감정으로 읽히면 안 된다.
또한 실제 세션에서 가장 큰 비중(40~50%)을 차지하므로, 채도가 있으면 화면을 지배해 버린다.

#### 검증 결과

`#FFFFF7` 바탕 기준, 무채색인 「중립」을 제외한 6색으로 검증했다.

| 항목 | 결과 |
|---|---|
| 명도 대역 (OKLCH L 0.43–0.77) | PASS — 6색 전부 |
| 채도 하한 | PASS — 6색 전부 ≥ 0.1 |
| 색각이상 구분 (인접) | PASS — 최악 `슬픔↔두려움` ΔE 8.2 (protan) |
| 정상 시각 구분 (인접) | PASS — 최악 `혐오↔슬픔` ΔE 16.2 |
| 바탕 대비 | 3색이 3:1 미만 → **직접 라벨 필수** (아래 조건) |

**조건**: CVD ΔE가 6~8 구간이고 일부 색의 바탕 대비가 3:1 미만이므로,
**색만으로 정보를 전달해서는 안 된다.** 다음을 항상 함께 제공한다.

- 모든 차트에 범례를 붙이고, 감정 이름을 글자로 쓴다
- 스택 바의 각 구간에 `%`를 직접 표기한다 (15% 이상인 구간)
- 전체 기록 표(감정 이름 + % 텍스트)를 항상 접근 가능하게 둔다

#### 색 배정 방법 (중요)

```ts
// ✅ 라벨 → 색
const EMOTION_COLOR: Record<EmotionLabel, string> = {
  happiness: "var(--e-happiness)",
  fear:      "var(--e-fear)",
  // ...
};
const color = EMOTION_COLOR[slice.label];

// ❌ 인덱스 → 색 — 차트마다 정렬이 달라 같은 감정이 다른 색이 된다
const color = CHART_COLORS[index % CHART_COLORS.length];
```

> 현재 코드는 ❌ 방식이다. [`reportMetrics.ts`](../frontend/src/utils/reportMetrics.ts)의
> `countsToSlices()`가 `DONUT_COLORS[index]`를 배정하고,
> [`ReportPage.tsx`](../frontend/src/pages/ReportPage.tsx)가 `CHART_COLORS[i]`로 다시 덮어쓴다.
> 그 결과 음성 도넛과 표정 도넛에서 같은 감정이 서로 다른 색으로 칠해진다.
> `DONUT_COLORS`는 항상 덮어써지므로 **한 번도 쓰이지 않는 죽은 코드**다 — 함께 제거한다.

## 2. 타이포그래피

테크/IT 페어링을 따른다. **국문 넥슨Lv.1고딕 · 영문 Space Grotesk.**

```css
--ui: "Space Grotesk", "NexonLv1Gothic", "넥슨Lv1고딕",
      -apple-system, BlinkMacSystemFont, "Apple SD Gothic Neo", "Pretendard",
      "Segoe UI", Roboto, "Noto Sans KR", system-ui, sans-serif;

--mono: ui-monospace, "SF Mono", SFMono-Regular, Menlo, monospace;
```

Space Grotesk에는 한글 글리프가 없다. 스택 맨 앞에 두면 **영문·숫자만 Space Grotesk로,
한글은 자동으로 다음 서체(넥슨Lv.1고딕)로** 떨어진다 — 국문/영문 페어링이 이 한 줄로 성립한다.

### 서체 조달

| 서체 | 조달 |
|---|---|
| Space Grotesk | Google Fonts — `fonts.googleapis.com/css2?family=Space+Grotesk:wght@400;500;600;700` |
| 넥슨Lv.1고딕 | Google Fonts 미제공. **웹폰트를 `frontend/public/fonts/`에 자체 호스팅**하고 `@font-face`로 등록한다. 미설치 시 Apple SD Gothic Neo / Noto Sans KR로 폴백. |

### 타입 스케일

| 역할 | 크기 | 굵기 | 자간 |
|---|---|---|---|
| 히어로 제목 | `clamp(38px, 5.6vw, 60px)` | 700 | -0.028em |
| 문서 제목 | 33px | 700 | -0.026em |
| 핵심 수치 | 36px | 700 | -0.028em |
| 섹션 제목 (h2) | 17–19px | 620 | -0.018em |
| 본문 | 15.5px / line-height 1.85 | 400 | -0.003em |
| UI 기본 | 13.5–15px | 400–550 | -0.003em |
| 라벨 (대문자) | 10.5px | 600 | **+0.1em** |
| 데이터 캡션 | 11–12px (mono) | 400 | — |

**자간 주의**: Space Grotesk는 원래 자족이 넓은 서체다. 영문 기준으로 조이면 한글이 뭉친다.
제목의 음수 자간을 -0.03em보다 조이지 않는다. 반대로 대문자 라벨은 +0.1em까지 벌린다.

**숫자**: 표·범례·수치처럼 자릿수가 맞아야 하는 곳은 `font-variant-numeric: tabular-nums`.

## 3. 형태

```css
--r-xs: 4px;   /* 색 견본, 작은 배지 */
--r-sm: 6px;   /* 버튼, 탭, 입력 */
--r:    10px;  /* 카드, 블록 */
--r-lg: 14px;  /* 말풍선, 큰 카드, 목업 프레임 */
```

### 그림자 — 3단계, 아껴 쓴다

```css
--sh-1: 0 1px 2px rgba(29,29,27,.04);                                   /* 버튼 */
--sh-2: 0 1px 3px rgba(29,29,27,.05), 0 8px 24px rgba(29,29,27,.05);    /* 떠 있는 패널 */
--sh-3: 0 2px 8px rgba(29,29,27,.04), 0 24px 56px rgba(29,29,27,.07);   /* 히어로 목업 1개만 */
```

`--sh-3`은 페이지당 하나만 쓴다. 여러 요소가 동시에 떠 있으면 위계가 사라진다.

### 여백

기준 단위 4px. 실제로 쓰는 값은 `4 · 6 · 8 · 10 · 14 · 16 · 20 · 26 · 34 · 44 · 60 · 92`.
섹션 사이는 44px 이상, 랜딩 섹션 사이는 92px.

## 4. 컴포넌트 규칙

### 버튼

| 종류 | 배경 | 테두리 | 글자 |
|---|---|---|---|
| `primary` | `--accent` (검정) | 검정 | `--accent-ink` |
| 기본 | `--surface` (순백) | `--line` | `--ink` |
| `quiet` | 투명 | 없음 | `--ink-2` |

### 큰 수치 밴드 (리포트 최상단)

리포트를 열었을 때 **가장 먼저 읽혀야 할 4개**를 36px 숫자로 세운다.
각 칸은 `라벨 → 큰 수치 → 보조 수치` 3층 구조.

```
발화 12회        소요 18분        음성·표정 불일치 3회     주된 감정 중립
평균 3.2문장     문항당 2분 15초   발화 4·6·10            음성 42% · 표정 50%
```

보조 수치는 장식이 아니다 — "불일치 3회"의 근거인 발화 번호처럼,
**바로 아래 섹션에서 확인할 수 있는 것**을 적는다.

### 차트

| 용도 | 형태 | 이유 |
|---|---|---|
| 감정 비중 (음성 vs 표정) | 가로 100% 스택 바 2줄 | 도넛 2개보다 세로 공간 1/3, 두 분포의 직접 비교가 가능 |
| 발화별 흐름 | 12칸 × 2행 타임라인 | 막대 24개를 한 줄로 압축. 불일치 지점이 한눈에 |
| 성향 vs 문화 (컬쳐핏) | 레이더 + 축별 수치 목록 | 레이더만으로는 값을 읽을 수 없어 목록을 함께 둔다 |

**금지**: 이중 축(y축 2개) 차트. 척도가 다른 두 측정치는 차트를 나누거나 공통 기준으로 지수화한다.

레이더는 도형만으로 값을 읽을 수 없으므로 **축별 수치 목록을 반드시 옆에 둔다.**
목록의 막대는 내 성향(검정 채움), 세로 눈금은 문화 기준선(`--ink-3`)이다.

### 카메라 미리보기

웹캠 프레이밍을 그대로 흉내 낸다 — **머리와 어깨가 프레임을 채우는** 구도.
얼굴 실루엣이 작게 떠 있으면 무엇을 보여주는 화면인지 읽히지 않는다.

- 비율 4:3, 배경 `--surface-2`
- 실루엣: 머리 원 + 어깨 곡선, `--ink-3` 42% 불투명도
- 검출 표시: 꽉 찬 사각형이 아니라 **네 모서리 갈고리 + 옅은 외곽선**
- 신뢰도·얼굴 수는 프레임 위에 떠 있는 배지가 아니라 **프레임 아래 한 줄**로

### 화면 폭

| 화면 | 폭 | 구성 |
|---|---|---|
| 랜딩 | `max-width: 1000px` | 중앙 정렬 단일 컬럼 |
| 면접 | `max-width: 1120px` | `1fr / 300px`, gap 56px |
| 리포트 | `max-width: 1040px` | `172px / 1fr`, gap 60px |

리포트는 **목차까지 포함한 전체가 중앙에 오도록** 그리드 자체에 `max-width`와
`margin: 0 auto`를 준다. 목차를 뷰포트 왼쪽 끝에 고정하고 본문만 가운데 두면,
넓은 화면에서 본문이 오른쪽으로 밀려 보인다. 1080px 미만에서는 목차를 감추고
본문을 `760px` 단일 컬럼으로 전환한다.

### 밝은 색 위의 글자

감정 색이 밝은 톤이라 **채움 위 흰 글자는 읽히지 않는다.**
스택 바 구간의 `%` 라벨은 진한 잉크색(`#171A1E`, weight 650)을 쓴다.

### 작은 색 견본

9~11px짜리 색 견본은 웜화이트 바탕에서 형태가 흐려진다. 옅은 안쪽 테두리로 잡아준다.

```css
.legend i, .emo i, .sig i { box-shadow: inset 0 0 0 1px rgba(26,29,33,.08); }
```

### 접기 (Toggle)

전체 기록처럼 **길지만 항상 필요하진 않은 것**은 `<details>`로 접어 둔다.
요약 줄에 항목 수를 표시한다 (`전체 답변 기록 · 12행`).

## 5. 리포트 구성

**필요한 것만 남긴다.** 순서는 요약 → 근거 → 해석 → 행동.

| 순서 | 섹션 | 내용 |
|---|---|---|
| 1 | 한눈에 보기 | 큰 수치 4 + 한 문장 결론 |
| 2 | 감정 분석 | 스택 바 2줄 · 타임라인 1줄 · (접힘) 전체 기록 |
| 3 | 면접 돌아보기 | 2문단 + 패턴/강점 2열 |
| 4 | 핵심 답변 | 2건 |
| 5 | **컬쳐핏 추천** | 랭킹 3 + 레이더 + 축별 수치 |
| 6 | 다음을 위한 질문 | 3건 |

**컬쳐핏은 탭이 아니라 문서 안의 섹션으로 둔다.** 탭 뒤에 숨기면 존재를 모르는 사용자가 생기고,
같은 세션 데이터의 다른 해석일 뿐이라 문서 흐름에서 자연스럽게 이어진다. 목차에도 항목으로 올린다.

덜어낸 것: 속성 표(제목 아래 한 줄 메타로 대체), 주제 태그, 탭 UI, 도넛 차트,
발화별 막대 24개(타임라인으로 대체).

| 1 | `styles/tokens.css` 신설 — 이 문서의 CSS 변수 전체. 감정 색 배정을 인덱스에서 라벨 기준으로 교체. `DONUT_COLORS` 제거 | 불필요 |

| 5 | 컬쳐핏 탭 — `types/cultureFit.ts` 타입 먼저 확정, 룰 기반 목데이터로 UI 완성 | 불필요 |
